# Master TestBook (AlphaTestbookapp)

Student test-prep PWA (SSC/RRB). Served by GitHub Pages from the repo root.

## Layout
- Root (`index.html`, `sw.js`, `manifest.webmanifest`, icons): the LIVE release. Never hand-edit `index.html`.
- `dev/app/`: source tree. Build: `cd dev/app && python3 build.py ../../index.html V2.x.y`.
- `dev/tests/`: Playwright suites; `fake_supabase.py` runs the real schema/RLS on local Postgres 16.
- `dev/server/SUPABASE_SCHEMA_V1.sql` + `V2.sql` + `V3.sql`: all applied on the live Supabase project (V2 = status/solutions, V3 = source_ref, 2026-10-16).
- `dev/tools/pyq-from-response-sheet/`: PDF → PYQ pipeline (`v2/` = generic version used for all SSC JE 2024 papers).
- `dev/tools/pyq-robot/robot.py` + `.github/workflows/pyq-robot.yml`: 🤖 PYQ Robot. User runs it from phone (Actions → PYQ Robot → paste SSC JE response-sheet links) — imports as draft with no Claude usage. Needs repo secret `SUPABASE_SECRET_KEY`. GA/Engineering land in topic "Mixed (Untagged)" (tag later); figure questions skipped. Test: `dev/tests/test_robot.py`.
- `dev/tools/hindi-robot/` + `.github/workflows/hindi-robot.yml`: 🌐 Hindi Robot. Fills empty `question_hi` (+ non-engineering option Hindi) with IndicTrans2 1B (pinned rev, MIT, `prajdabre/rotary-indictrans2-en-indic-1B`), 8 parallel shards, runs after every PYQ Robot run. Protects codes/names/maths/units; never overwrites Hindi; marks source_ref "· Hindi = machine translation (IndicTrans2)"; changes content_hash so students resync. Needs transformers 4.46.x. Test: `dev/tests/test_hindi.py`.
- `dev/tools/tag-robot/tagger.py` + `.github/workflows/tag-robot.yml`: 🏷️ Tag Robot. TF-IDF + logistic regression learns from hand-tagged questions per subject; moves Mixed questions only if subject CV accuracy ≥ 80 % and prob ≥ 0.55; changes only topic_id/chapter/topic/content_hash. Runs after PYQ Robot. Test: `dev/tests/test_tagger.py`.
- `dev/tools/key-check-robot/keycheck.py` + `.github/workflows/key-check-robot.yml`: 🔑 Key-check Robot. READ-ONLY (never edits a question). Flags: A structure (answer/4 options/duplicate options), B same question in two papers with different answer text, C one paper where a letter is the key for >45 % of ≥20 Q, D optional Gemini second opinion (free key `GEMINI_API_KEY`, only question+options sent, ~4.5 s between calls, `--limit/--offset` for the free quota). Official key stays the truth; D is only "जाँचो". Runs after PYQ Robot (draft) or by hand (draft/published/all). `--strict` exits 2 on hard flags (A/B) for a later auto-publish gate. Test: `dev/tests/test_keycheck.py`.
- `dev/tools/health-robot/health.py` + `.github/workflows/health-robot.yml`: 🩺 Health Robot. Every 2 h + after every robot/test run: live site version, GitHub workflow results, Supabase counts (questions live/draft/hidden/broken/untagged/no-Hindi, students/answers/tests — COUNTS ONLY, repo is public). Pushes status.json + history.json to branch `status`; red → opens/updates issue "🚨 App health: ध्यान दो" (closes itself when green). Page `control/index.html` (Control Room, not built, not cached by sw) reads raw status branch + live GitHub runs. Test: `dev/tests/test_health.py`.
- `dev/server/SUPABASE_SCHEMA_V4.sql` (applied 2026-10-17, without DROPs — the live apply uses plain CREATE; the file has guarded DO blocks): Control Room backend — `ops_settings` (switches/policies; only `maintenance` is public), `ops_requests` (admin queue), `ops_audit` + trigger on questions/topics/settings (actor from `x-actor` header or login email, `ops.reason`), `ops_revert`, `ops_question_action` (publish quality gate), `ops_incidents`, `ops_runs`, `ops_client_errors` (30/h/user), `backup.snapshots` + `ops_backup_now/list/verify`, `ops_restore_questions` (needs `RESTORE-<id>`, takes a safety snapshot, never deletes), `ops_db_stats`. Migrations with DROP/DELETE get cancelled by the connector — avoid them.
- `dev/tools/ops/`: `opslib.py` (gate step in every robot: pause/disable/freeze; run records), `ops_robot.py` + `ops-robot.yml` (every 10 min: run/cancel/emergency-stop/backup/rollback requests, GITHUB_TOKEN only, allow-listed), `backup_robot.py` + `backup-robot.yml` (nightly 02:37 IST). `rollback.yml` restores live index.html/admin of a tests-passed commit (source untouched; sw cache gets `-rb`). Robots send `x-actor: <name>-robot`. Test: `dev/tests/test_ops.py` (fake_supabase now supports rpc, count, or/is/like filters).
- `control/` (index.html + cr.js + cr.css, not built, not cached by sw): Control Room, 22 sections. Public = status.json; admin (shared login `mtb_server_session_v1`) = live Supabase actions. Student app: `src/js/17c-ops-client.js` = maintenance banner + error reports.
- `dev/server/SUPABASE_SCHEMA_V5.sql` (applied 2026-10-17, backup #3 first): roles on `admins.role` (owner/admin/operator/readonly; `ops_role/ops_perm/ops_need`, `ops_admin_list`, `ops_set_role` owner-only, last owner protected), `ops_tasks` (Task Manager: steps/checkpoints/logs/approval/verification/report, dedupe; `ops_task_create` → negative id = duplicate active, high-risk execute → waiting_approval; `ops_task_control` approve/reject/pause/resume/cancel/retry), `ops_events` (feature usage, 400/day/user) + `ops_usage_stats(days)` (aggregate only), import_batches.source_url/report, seed settings (ops.lease, retry.auto/max, finance.assumptions).
- Ops Robot task engine (`ops_robot.do_tasks`, lease, also run by Health with `--budget 60`): step types workflow · backup · verify_backup · verify_links (→ pyq step `use_verified`) · setting · cancel_runs · merge_branch (restore/* only) · publish_passing · note. Auto-retry once for health/backup/keycheck/tests.
- New workflows: `design-audit.yml` (dev/tools/design-audit/audit.py, weekly + manual, report only), `smoke.yml` (after Tests on main: live version = code + app/admin/control open), `selective-restore.yml` (only dev/app/src/ or control/ files from an old sha → branch restore/*, full tests; main untouched; merge = high-risk task approved by owner).
- Control Room V3.4 = `control/cr.js` (core, registry VIEWS/ON_GO/EXTRA_ACT, deferred boot) + `control/cr-command.js` (🧠 Command Console: rules intent engine Hindi/English, ASK/PLAN/EXECUTE, follow-ups, facts with source+time; 📋 Tasks; 📦 Imports; 🎨 Design history + selective restore; 💰 Finance (estimates); feature-usage analytics, roles UI, robot calendar). No paid AI. App sends events via `src/js/22e-ops-events.js`.
- `dev/server/SUPABASE_SCHEMA_V6.sql` (applied 2026-10-17, backup #4 first): private Storage bucket `pyq-uploads` (PDF only, 20 MB), upload only by admins with 'run'. Control Room → 📦 PYQ Imports → PDF upload. Ops Robot step `upload_link` makes a 1-hour signed link at dispatch time; the link/token is never saved in tasks. Link checks send browser-like headers; a 403 says "साइट ने robot को रोका — upload करें".
- Lanes: data robots/tools work on branch `data-robots`, UI/design on `design-v3`; never mix both in one PR. Merge to main only after all suites pass.
- Server changes: Claude applies them via the Supabase connector. Take a backup into schema `backup` first; avoid DROP (needs extra confirmation) — use ALTER / IF NOT EXISTS.

## Release rules
1. Change source in `dev/app/src`, bump version (head-01.html meta + build arg).
2. Bump `CACHE` name in `sw.js` (mtb-shell-vN) on every release.
3. Run `dev/tests/run_all.sh` (all suites); push only when all pass.
4. Questions change only through `DataCore.commit/mutate` — never assign AppModules directly.

## Never
- Never put Supabase secret/service_role keys, DB password or OAuth client secret in the repo. Only the publishable key is allowed.
- Never strip publisher names/watermarks or copy publisher solutions. Only official PYQ text/options/answers + our own solutions.
- User works from an Android phone only (no laptop); explain steps in simple Hindi.
